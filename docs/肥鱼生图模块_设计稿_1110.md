## 一、红线 (拍板重申, 全部硬编码, 不留开关)

1. **非 R18 双层闸**: 负向焊死 (`nsfw, suggestive, nude, ...` 固化在模块, 无改负向接口) +
   正向词表闸 (R18 词黑名单命中即拒单)。
2. **真人声优/偶像名字形象一律拒单** (不随 style 变): 内置真人名单 + "真人/本人/声优/偶像/爱豆/中之人"
   指示词扫描, 命中拒单。
3. **洗图硬闸**: 图在进任何外传路径 (QQ/直播间) 之前**必剥元数据** (ComfyUI PNG 的 tEXt
   含完整节点图=明文提示词)。硬闸没过 = 不出目录。凡发现一张没剥的图出去, 整条链路停线整改。
4. **直播推流中禁止自动重启 ComfyUI** (显存打架打崩直播帧率, 宁可这单失败)。
5. **不动 DSH 插件层** —— 模块全在 PC 侧, 对外只有 MCP 工具面。
6. 负向禁数字趾数词 (铁律), 落盘进 `_问题隔离/` 不删, 每成功批必落档。

## 二、架构 (通道现成, 零新开口)

```
她(QQ) ──► 云上大脑(dsh-web) ──► MCP 工具 gen_image ──► 隧道 ──► PC 本机
                                                                  │
                ┌─────────────────────────────────────────────────┘
                ▼
   feiyu_image_mcp.py (:18082, streamable-HTTP MCP, BWF 同协议)
     ├─ 拒单双闸 (R18 词表 / 真人名单) ─── 命中: 返回 {ok:false, reason}
     ├─ 拼 prompt (画风基线钉死, ≤750 字硬闸)
     ├─ ComfyUI 生命周期: 探活 8188 → 拉起(--disable-comfy-compiler) / 直播互锁拒单
     ├─ 提交 + 轮询落盘 (xufufu_api_template.json 拓扑, 节点77)
     ├─ 洗图硬闸 strip_gate() (逐张剥 tEXt/EXIF + 像素校验, 失败=该图不出目录)
```

- **隧道**: `remote-proxy.py` MAP 追加一行 `17853→18082` (只绑 Tailscale 100.98.120.55,
  与 BWF 的 17852→18081 同款, 公网不可达 → 满足"零新开口")。os 拍板文里的"47852"
  疑为 17852 笔误, 已在 M1 汇报里确认。
- **对外只以 MCP 工具面世**, HTTP 端口不对她开放, 只给隧道/本机。

## 五、18081 BWF MCP 注册格式对齐笔记 (实测 54 工具)

- **协议**: streamable HTTP JSON-RPC, 端点 `/mcp`; 客户端 `POST` 带
  `Accept: application/json, text/event-stream`; 响应头回 `mcp-session-id`,
  后续请求带同头; 响应体是 SSE (`data: {...}` 行), 无 session 时直接 JSON。
  握手: `initialize`(protocolVersion `2025-03-26`) → `notifications/initialized` → `tools/list` / `tools/call`。
- **工具注册格式** (实测 get_state / fish 两个样例):
  ```json
  {"name": "fish", "description": "钓鱼:自动在附近找岸边…(中文, 动作导向, 自含约束)",
   "inputSchema": {"type": "object", "properties": {
       "casts": {"type": "integer", "description": "抛竿次数 1~20, 默认 5"},
       ...}, "required": []}}
  ```
  规律: name 英文 snake_case; description 中文一段话写清"做什么+前置条件+默认值+约束";
  每个参数带中文 description; 能省的参数全部可省 (`required` 常为空)。
- **返回**: `tools/call` → `result.content[0].text` (一段文字/JSON 字符串)。BWF 是业务文字,
  本模块返回紧凑 JSON (`ok/reason/images/batch_dir/audit`), 桥和大脑都好解析。
- 参考调用器: `D:\StardewAI\_bwf.mjs` (一次性的 initialize→initialized→call 三连)。

## 六、ComfyUI 生命周期 (M3 代码就位; 显存驱动, 用户 1110 指令)

**用户指令 (1110)**: 探测剩余显存 → 不够就不拉起生图任务 (判定在玩大型游戏);
已有生图任务就插队 (直接投同队列); 没有生图任务就自己拉起服务;
**生图结束后自动卸载模型** 把显存还给游戏。

1. **探活**: `GET 8188/system_stats` 3s 超时。
2. **显存闸**: `nvidia-smi` 查 memory.free; `VRAM_MIN_GB = 9.0`
   (SDXL 全链常驻约 8.1GB 实测 + 工作余量)。探不到 = 不能确认余量 → 保守拒拉起。
   ComfyUI **已在线**则跳过显存闸直接投 (模型已常驻, 插队零额外开销)。
3. **拉起** (仅离线且过闸时): `G:\ComfyUI` 下 DETACHED 进程
   `python -B main.py --listen 127.0.0.1 --port 8188 --force-fp16 --disable-api-nodes
   --disable-comfy-compiler --output-directory G:/生图工作盘/ComfyUI_output`
   (**output-directory 必须正斜杠**, Git Bash/Windows 双坑已录 AGENTS);
   日志落 `server/logs/comfy8188_*.log`; 拉起后探活最长 300s。
4. **直播互锁** (os 1110 拍板): 进程名含**「哔哩哔哩」或 `livehime`** = 推流中,
   宁保守 (开着就算); **不用** live_host `/healthz` 的 obs.streaming 当判据
   (推流走直播姬不走 OBS, 实测房间在播时 obs.streaming=false)。
   直播中 → 只许用**已在线**的 ComfyUI, 绝不拉起/重启。
5. **插队**: ComfyUI 在线时无视队列长度直接投 (FIFO); `GET /queue` 只用于收尾判断。
6. **自动卸载** (收尾): 本单落盘且 `/queue` 排空 → `POST /free {"unload_models":true,
   "free_memory":true}` 归还显存; 队列还有别人 (插队场景) 就不卸, 只记账。
   核心不支持 /free 时记账如实报 (只能重启释放)。
7. **守夜人报备**: 条目见 docs 本节末尾 (os 侧并进自启清单)。

## 七、洗图硬闸 (M2 先行, 独立函数 + 单测)

- `strip_gate(src_dir)` — 逻辑照抄 `G:\生图工作盘\洗图工具\strip_meta.py` (像素级无损重存:
  PNG 逐块过滤只留 IHDR/PLTE/IDAT/IEND/tRNS/iCCP/sRGB/gAMA; JPEG 只留 SOI+SOS 扫描+EOI;
  WEBP 剥 EXIF/XMP/ICCP 块), **独立函数内嵌本模块**(跨仓 import 脆弱), 单测三断言:
  ① 剥后 `im.text` 为空 ② `pixels_equal` maxdiff==0 ③ 伪造带 tEXt prompt 的 PNG 过闸后读不到 `prompt`。
- **出目录规则**: 原图(带 prompt)落 `ComfyUI_output/肥鱼OS/<批次>/raw/` (仅本机, 不外传),
  洗净版落 `ComfyUI_output/肥鱼OS/<批次>/` —— **工具返回给她的路径只有洗净版的**,
  原图路径不出现在任何 MCP 返回里。
- 备份纪律: strip 前先备份原图到 raw/ (等价于洗图工具的备份步骤)。
