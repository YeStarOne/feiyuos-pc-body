# 2026-11-10 鱼鳍系统（`fin`）+ 开机两只桌宠修复

## 一、鱼鳍系统：云上的她可以动手了（主人拍板）

### 之前
她只有**眼睛**（eye-server 定期抓屏 → 视觉笔记）和**嘴**（pet_say 双投递气泡+QQ）。
要用 PC 上的任何东西——读一份文档、跑一条命令、改一个文件——都得找主持代劳。

### 现在
`pc_body.py` 多出 `/fins/*` 七个端点，PC 侧实现在 `pc_fins.py`，云端多一个 CLI `fin`
（`server/fin`，装到 `/usr/local/bin/fin`）。链路完全复用现有反向 SSH 隧道：

```
云上 shell: fin exec "dir D:\"
   → 127.0.0.1:47860（反向隧道） → PC 17860 → pc_fins.exec_cmd() → cmd /c
```

大脑和会话仍然只有云上那一个 —— 这是给她加**手**，不是开新实例。

### 端点
| 端点 | 参数 | 说明 |
|---|---|---|
| GET `/fins/status` | — | enabled / limits / off_flag / 拒绝表条数 |
| GET `/fins/list` | dir,q,ext,limit | dir 空 = 盘符列表；目录始终列出，ext 只筛文件 |
| GET `/fins/read` | path,offset,max,b64 | 单次 ≤40000 字，返回 `next_offset`；docx/xlsx 抽成文本 |
| GET `/fins/stat` | path | size/mtime/readonly |
| GET `/fins/audit` | n | 最近动作台账 |
| POST `/fins/exec` | cmd,cwd,timeout_s,shell(cmd\|ps) | 输出走临时文件（不死锁），两路各截 200KB，真大小上报 |
| POST `/fins/write` | path,content\|b64,append | 自动建父目录 |

只认 Bearer（与鱼眼同一枚 `.eye-token` / 云上 `~/.dsh/eye-server.token`），**不进** query-token 白名单
（平板只该有气泡和表情）。

### 护栏（都在 `pc_fins.py`，配置在 `pc/fins.json`）
- `fins.off` 文件存在（或 `FEIYU_FINS=off`）→ 一切动作返回 `fins-off`；实测踩下/松开各一次，不改代码不重启。
- 每条动作写 `logs/fins_audit.jsonl`（5MB 轮转），`fin audit` 可查。
- 禁读凭据类：`.ssh/ .aws/ .gnupg/`、`id_rsa*`、`*.pem/.key/.pfx/.p12/.ppk/.kdbx`、`.eye-token`、
  `.git-credentials`、`.netrc`、`keys_tmp/`、`admin-password`。
- 禁写系统目录：`C:\Windows`、`Program Files*`、`ProgramData\Microsoft`、回收站/系统卷信息。
- 灾难命令直接拒：`format X:`、`diskpart`、`bcdedit`、`vssadmin delete`、`cipher /w`、
  盘根级 `rd/del /s`、`mkfs`、`dd if=` —— 防手滑，不防人。
- 超时（默认 20s，上限 300s）`taskkill /T /F` 杀整棵树；并发上限 4。

### 证据（都是真请求，不是推演）
- `fin exec "hostname && ver"` → `HJH202505131727` / `Windows 10.0.26100.4061`
- `fin exec "exit /b 7"` → 退出码 7（CLI 透传远端退出码）
- `fin exec --ps "(Get-Date)"`、`--cwd G:\量化系统安装包`（中文路径）
- `fin read D:\StardewAI\dsh-pet\README.md`、`fin ls ... --ext md`、`fin stat`
- `echo ... | fin write G:\tmp\fins_e2e\hello.txt --from -` → 读回一致
- `fin exec "format z: /q"` → `denied`（未执行），审计里一行 ERR
- 单测 `python -B pc/test_pc_fins.py` → 26/26；HTTP 层另跑 22/22（含 query-token 401、超时、b64、审计）

### 坑
- **`.bat` 里不能写中文注释**：UTF-8 无 BOM 被 cmd 按 GBK 解析 → 乱码当命令执行。
- Git Bash 会把 `taskkill /PID` 里的 `/PID` 当路径（`D:/Program Files/Git/PID`）→ 用 `cmd //c "taskkill /F /PID n"`。
- 命令输出走临时文件而不是 `PIPE`：否则超时 kill 后管道里的孙进程仍攥着句柄，`communicate()` 卡死。
- `Path.read_text()` 会把 CRLF 归一化 —— 改 `.bat` 必须 `open(newline='')` 拿原始字节，否则改完再写回去整文件换行全变。

## 二、开机两只桌宠（同一晚修掉）

**真因**：`start_pet_body.bat` 既起常驻看门狗，又跑一次 `wd_pc_body.py once` 预热。两者同一秒都探到
`:7340` DOWN，各拉一份 `lib/standalone.js`。单胜者假设只对 `pc_body.py` 成立——`standalone.js`
绑端口失败**不退出**，带着 Electron 子进程继续活着 = 一只不接请求的假桌宠。

**修法**：删掉预热（常驻看门狗启动即 `check_pass()`，本就不需要）；`wd_pc_body.py` 加
`reap_extra_pet()`：`:7340` 活着时，杀掉「cmdline 含 `standalone.js` + `--port 7340` + 不是端口属主」
的 node（`taskkill /T /F`），10 分钟最多一次。

**证据**：日志同一秒两条 `DOWN 7340 -> 拉起`；`reap` 实跑清掉 pid 31396（属主 33048）；屏幕 1 个窗口，
`:7340` 200，看门狗换新 pid 2736 持 `:17861`。
